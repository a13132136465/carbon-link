| R04 会话撤销 | 新增 `users.token_version`；改密、重置和角色/启用状态变化撤销旧会话及其他未使用重置令牌；前端改密后退出登录 |

| R07 上传内存风险 | 按流累计大小，超限或异常删除文件；接收期间不持有数据库事务，提交文件记录前重新加锁核对项目状态 |
| R08 竞争审批 | 编辑、删除、提交、审批和材料变更遵循项目行锁；锁后刷新旧 ORM 状态，竞争审核只有一方成功 |
| R09 注销用途 | 将请求用途按 UTF-8 做 keccak，与链上 `evidenceDigest` 严格比对；不额外进行 Unicode 归一化，保持钱包签名原文语义 |
| R10 nonce 竞争 | PostgreSQL 会话级账户锁跨越准备/提交/广播；已签名任务持久化签名账户与 nonce，分配时结合数据库预留和链上 pending nonce |
| R11 确认异常/阻塞 | 确认异常写回错误和退避；同一轮检查确认和新任务；掉池只重播同一原始交易，保留首次广播时间；结果不明进入 `needs_attention` 并继续观察回执 |
| R12 旧账本误导 | 累计签发/注销直接汇总已确认区块的全部链上批次，与市场统计共用快照；链上模式拒绝旧资产流水查询并显示钱包/区块浏览器提示 |
| R13 Agent 假成功 | 区分 finish、blocked、failed；finish 必须带可见完成文本；CLI 不再将受阻结果统计为通过 |
| R14 漏洞依赖 | 升级 FastAPI / Starlette / PyJWT / pytest，删除无调用的依赖链，加入完整已解析版本约束并用于 Docker 安装 |

R12 后续按用户要求补充直接链上读取：利用当前 `CarbonCreditLedger` 从 1 连续分配且不删除批次的约束，通过 `getBatch` 探测批次边界，再分组汇总 `totalIssued` / `totalRetired`。范围为配置的额度合约全部批次，包括未同步到本地数据库的批次、冻结批次及链上直接注销。数量按 10,000 基础单位/吨换算。只有匹配批次 ID 的 `BatchNotFound` 才视为边界，RPC 错误或其他 revert 不返回伪造的零值。

签发、注销和市场使用同一个达到 `BLOCKCHAIN_CONFIRMATIONS` 要求的区块快照，读取完成后再次核对区块哈希；检测到重组返回 503，需重试。新交易达到确认数后，下一次页面加载才计入。总览恢复碳影响力卡片，空值按 0 显示。报价币种改用明确的 `blockchain_enabled` 字段，不再通过统计是否为空推断。

本次采用直接读取，未建立后台事件索引，不需部署新合约或新增迁移。每次请求的读取量随批次数与市场历史增长（批次分组 128、最多 12 并发）；大规模数据应进一步增加缓存或事件索引。钱包历史仍未建立索引，继续显示“暂未汇总”。

此外，浏览器 RPC 改为独立公开配置；前端订单簿使用固定区块和最多 8 个并发读取，避免重叠轮询；近 200 笔范围内的 24h 指标明确标注采样范围；修复 Nginx 页面/静态资源安全头继承。

合约生产源码及资产规则没有变更，不需要重新部署。项目撤销、批次冻结、舍入归属和暂停撤单边界在合约说明中明确，并补充舍入守恒及暂停退出测试。此次没有添加完整的账号配额/分布式限流服务；公网部署仍应在可信网关配置认证、邮件和模型请求限流。

## 依赖检查与清理

后端移除：

- `langchain`、`langchain-openai`、`langgraph`：当前申报 Agent 直接使用 OpenAI SDK，应用无对应导入。
- `python-multipart`：附件上传使用 raw body 流，接口没有 `Form` / `UploadFile` 声明。
- 上述清理同时移除了不再被需要的 LangChain core/text-splitters、LangGraph checkpoint/sdk 等传递依赖。

实际验证版本：FastAPI 0.142.2、Starlette 1.7.0、PyJWT 2.15.1、pytest 9.1.1、OpenAI 2.54.0。其他运行依赖保留实际业务用途，包括数据库迁移、邮件地址校验、密码哈希、PostgreSQL 和 Web3。

`requirements.lock` 记录 Python 3.12/Linux 环境的解析版本，作为 pip constraints 使用：只限制被选中的依赖，不会让生产镜像自动安装测试工具。此文件不是带下载哈希的跨平台锁文件；跨平台更新应重新验证。Docker 和 README 安装步骤均已使用该约束。

前端保留实际使用的 React、Router、Ethers 和图表库；把 Vite、TypeScript、React 构建插件移到 devDependencies，并按原锁文件版本精确固定，移除 `latest`。用户 Agent 的四个运行依赖均有直接用途，因此保留。

干净环境及约束集合的依赖扫描：Python **0 条已知漏洞**，前端及用户 Agent 的 npm audit 均为 **0 条**。扫描结果仅代表当日公告匹配，不是对未来漏洞或操作系统镜像漏洞的保证。

## 现有部署升级顺序

1. **先备份数据库和旧 API 容器中的附件。** 在重建旧容器之前复制 `/app/uploads`；不要直接执行会销毁旧容器的重建步骤。旧附件不会自动进入新卷。
2. 停止旧 Worker 和 API 的写入；保存当前 Compose 项目名、数据库备份及附件清单/哈希。
3. 更新环境配置。启用链上模式时新增必填 `BLOCKCHAIN_PUBLIC_RPC_URL`，使用可公开、与 `BLOCKCHAIN_CHAIN_ID` 一致的端点，不包含私有供应商 key。服务端仍使用 `BLOCKCHAIN_RPC_URL`。可设置 `BLOCKCHAIN_TRANSACTION_TIMEOUT_SECONDS`，默认 1800 秒。
4. 使用约束文件构建镜像，运行 `alembic upgrade head`。Compose 的 API 启动命令仍自动执行迁移；首次启动前应已完成备份。新增 0006 不删除业务数据。
5. 把备份材料恢复到当前 Compose 项目的 `uploads_data` 卷，保留相对目录，并使容器内 `app` 用户可读写。验证材料数量和哈希后再开放写入。
6. API 与 Worker 使用同一 PostgreSQL 数据库。启用签名 Worker 不再支持 SQLite；SQLite 只用于非链上本地功能/测试。签名账户由本系统专用，外部发交易程序不能参与本系统数据库锁。
7. 检查历史 failed/prepared/submitted 任务及旧 nonce，确认没有未核对的广播结果后启动 Worker。`needs_attention` 保留签名原文和 nonce：先对照链上回执、账户 latest/pending nonce 核对，再决定运维恢复；不要删原始交易或随意清空 nonce 重新签名。
8. 旧 JWT 因缺少会话版本字段失效，用户需重新登录。找回密码必须经邮件完成。原来通过旧接口无材料进入 pending 的项目需驳回补齐材料，不能直接批准。
9. 验证上传下载、改密重新登录、两个审核者竞争、链上证书及任务队列。核对总览链上累计值；钱包历史未索引的页面继续保持“暂未汇总”，不能改回旧账本数值。

本次未执行上述真实部署升级步骤，避免重建旧 API 时丢失其尚未迁移的附件。原审计报告保留为历史快照，修复状态以本文件和当前代码为准。
